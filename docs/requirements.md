# 人事評価業務の現状・課題・改善したい方向性

## 1. 背景・目的

現在、社内の人事評価にGoogleフォームを利用している。

メンバーがGoogleフォームに自己評価を入力・提出し、その内容を面談担当者やマネージャー、社長などが確認・評価する運用となっている。

ただし、現在の仕組みでは、評価情報がどのように受け渡され、どこに保存され、誰がどの情報を確認・編集しているのかといった内部的な処理がメンバー側から分かりにくい。

また、最終的な評価結果は口頭で本人に伝えられることが多く、本人がその内容を聞きながらメモに書き起こす必要がある。

こうした情報伝達や評価結果の管理に関する手間を削減し、よりスムーズに人事評価を実施できるWebシステムの構築を検討している。

## 2. 現在の業務フロー

現在の業務フローは、おおむね以下のとおり。

### ① メンバーによる自己評価

- メンバーがGoogleフォームにアクセスする。
- 氏名や所属などの基本情報を入力する。
- 複数の評価項目について自己評価を記入する。
- 入力が完了したらGoogleフォームを提出する。

Googleフォームは全体で8～9ページ程度の構成となっている。

各ページには、評価対象となる項目について以下の入力欄が設けられている。

- 1～5の5段階評価
- その評価に対する補足コメント・自己評価の根拠などを記入する欄

評価対象には、例えば手法や報告書に関する業務上の項目、勤怠や日頃の行動に関する項目などがある。

そのため、単純に全体を総括して評価する形式ではなく、個々の評価項目に対して評価点とコメントを記入する形式となっている。

### ② 面談担当者による内容確認・取りまとめ

- 提出された自己評価の内容を面談担当者が確認する。
- 自己評価の内容を踏まえ、面談担当者が内容を整理・取りまとめる。
- 必要に応じて、自己評価に対する補足や所見などをまとめる。

ここでいう面談担当者とは、必ずしも「リーダー」という役職に限定されない。

会社の組織や人員配置によって、リーダー、サブマネージャー、マネージャーなどが面談を担当する場合がある。

そのため、システム上では特定の役職名ではなく、面談を担当する側の役割として扱うことが望ましい。

### ③ マネージャー・社長による評価

- メンバー本人の自己評価を確認する。
- 面談担当者が取りまとめた内容を確認する。
- マネージャーや社長が評価を行う。
- 評価内容を記入・整理する。

### ④ 面談担当者による評価内容の確認

- マネージャーや社長が記入した評価内容を面談担当者が確認する。
- 確認した評価内容を踏まえ、本人への評価結果の伝達に進む。

### ⑤ メンバー本人への評価結果の伝達

- 面談担当者からメンバー本人に最終的な評価結果が伝えられる。
- 現状では、評価内容を口頭で説明することが中心となっている。
- メンバー本人は、説明された内容を聞きながら必要な情報をメモする。

## 3. 現在の業務における問題点

### ① 評価情報の流れが分かりにくい

Googleフォームを起点として、自己評価や面談担当者の取りまとめ内容、マネージャー・社長の評価などがどのように管理・共有されているのか、メンバー側からは把握しにくい。

Googleフォーム、スプレッドシート、その他のWebシステムなど、具体的にどのような仕組みでデータが保存・受け渡しされているのかも明確ではない。

### ② 評価結果が口頭で伝達されている

マネージャーや社長が記入した評価内容について、本人にそのままデータとして共有するのではなく、面談担当者を介して口頭で伝える運用になっている。

そのため、本人は説明を聞きながら評価内容をメモする必要がある。

### ③ 評価内容を本人が後から確認しにくい

口頭で伝えられた内容を本人がメモする形式では、説明された内容を正確に記録できない可能性がある。

また、後から評価内容を確認したい場合にも、自分で記録したメモを見返す必要があり、正式な評価結果を簡単に参照できる仕組みがない。

### ④ 評価情報の管理・共有が不透明

自己評価、面談担当者による取りまとめ、マネージャー・社長による評価など、複数の段階で情報が作成されるが、それぞれの情報がどのように保存・管理されているのかが分かりにくい。

## 4. 改善したい方向性

現在の人事評価の仕組みや評価方法を大きく変更することが目的ではなく、現在の業務フローを維持しながら、情報の受け渡しや管理をWebシステム上でスムーズに行えるようにしたい。

特に、以下の点を改善したい。

- Googleフォームで実施している自己評価の入力・提出をWebシステム上で行えるようにする。
- 自己評価の内容を面談担当者が確認し、取りまとめられるようにする。
- 面談担当者が整理した情報と、マネージャー・社長が記入した評価情報を管理できるようにする。
- 評価の各段階で作成された情報を、適切な権限を持つ担当者が確認できるようにする。
- マネージャー・社長が記入した評価内容を、最終的にメンバー本人へデータとして共有できるようにする。
- メンバー本人がログインすれば、自分の評価結果をいつでも確認できるようにする。
- 口頭での評価結果の伝達や、本人による手動でのメモ作成を不要にする、または大幅に削減する。

## 5. 関係者の役割について

システム設計上、関係者は大きく以下の3つの役割に分けて考えたい。

| 役割 | 説明 |
|---|---|
| メンバー（被評価者） | 自己評価を入力・提出し、最終的な評価結果を確認する人 |
| 面談担当者 | メンバーとの面談を担当し、自己評価の内容を確認・整理し、評価結果を本人に伝達する人 |
| マネージャー・社長（評価決定側） | 自己評価や面談担当者の取りまとめ内容を確認し、評価を記入・決定する人 |

※面談担当者は固定の役職ではない。リーダー、サブマネージャー、マネージャーなど、実際に面談を担当する人がこの役割を担う場合がある。

※マネージャーが面談担当者と評価決定側の両方を担う場合も考えられるため、役職とシステム上の役割は必ずしも一致しない。

## 6. システム設計にあたっての前提・補足

- 現在の評価項目や評価方法は、基本的に維持する方向で考えている。
- 自己評価は、全体を一括して評価する形式ではなく、複数の個別評価項目に対して1～5の評価点と補足コメントを入力する形式である。
- Googleフォームは氏名・所属などの基本情報に加えて、約8～9ページの評価項目で構成されている。
- 評価項目ごとの評価点とコメントを個別に管理できることが重要。
- 全体を総括するコメントも必要になる可能性はあるが、基本的には各評価項目に対するコメントを中心に扱いたい。
- 最終的な評価内容を本人が直接確認できることを重視している。
- 評価情報には機密性があるため、役割に応じた閲覧・編集権限を考慮する必要がある。

## 7. 今回検討したいこと

上記の現状・課題・改善したい方向性を踏まえ、現在の業務フローを大きく変えずに、より効率的に人事評価を実施できるWebシステムを検討したい。

特に以下の観点で設計案を考えたい。

1. 現在の業務フローを踏まえた、現実的な改善後の業務フロー
2. 関係者ごとの画面構成と操作内容
3. 自己評価・面談担当者の取りまとめ・管理職評価のデータ管理方法
4. 評価の入力・確認・確定・本人への公開の仕組み
5. 閲覧・編集権限の設計
6. 評価結果を本人に共有する方法
7. 実装・運用コストを抑えたシステム構成

単に新しい評価制度を作るのではなく、現在の業務で発生している情報伝達の手間や管理の不透明さを解消することを重視する。

## 8. 補足（追記）

- 「マネージャー・社長（評価決定側）」は1人ではなく2人いる。1人は面談担当者と社長の間に位置するマネージャー、もう1人は社長である。別々の人がそれぞれログインして評価する。
- 実装では、面談担当者の取りまとめ → マネージャーの評価 → 社長の評価 → 面談担当者の確認・公開 の順に進める想定とした（順序・各自が項目ごとに評価点とコメントを付ける点は想定であり、要確認）。
